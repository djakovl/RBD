# Проект: распределённая БД системы регистрации инцидентов и самовосстановления (объект КИИ ↔ центр)

Индивидуальный проект по дисциплине «Распределённые и облачные базы данных».

## Структура

| Путь | Назначение |
|---|---|
| `stand/` | Стенд: 2 узла PostgreSQL (центр, объект) + pgAdmin, запуск через podman |
| `stand/center/`, `stand/site/` | DDL и данные узлов (выполняются автоматически при первом старте) |
| `stand/links/` | SQL для FDW и логической репликации (применяет `setup_links.sh`) |
| `scripts/` | Генератор событий, сценарии обрыва/возврата канала |
| `docs/` | Заявка, схема, отчёт (следующий коммит) |
| `client/` | Демонстрационный клиент на Rust (следующий коммит) |

## Узлы стенда

| Узел | Контейнер | БД | Роль |
|---|---|---|---|
| Центр мониторинга | `rbd_center` | `rbd_center` | Пишет справочники (`ci`, `remediation_policy`, `operator`), журнал `incident`, витрину; читает очередь объекта через FDW |
| Объект КИИ | `rbd_site` | `rbd_site` | Пишет `anomaly_event` (очередь), `local_incident`, `remediation_action`; держит реплику справочников (логическая репликация) |
| pgAdmin | `rbd_pgadmin` | — | Просмотр данных обоих узлов |

Критерий распределения: по контуру (объект ↔ центр) и режиму доступа — оперативные события лежат на объекте и не покидают его до синхронизации, справочники и архив — в центре. Подробности — в заявке.

## Запуск

Требуется podman 4.x+ (поддерживает `podman compose`) или podman-compose.

    cd stand
    podman compose up -d      # поднять узлы (при первом старте выполнятся init-скрипты)
    ./setup_links.sh          # FDW в обе стороны + логическая репликация справочников
    cd ..
    ./scripts/feed_data.sh 3  # поток синтетических событий (Ctrl+C — стоп)

Подключение:

- центр: `127.0.0.1:5432`, БД `rbd_center`, пользователь `center`
- объект: `127.0.0.1:5433`, БД `rbd_site`, пользователь `site`
- pgAdmin: http://127.0.0.1:5050 (`admin@local` / `admin`); серверы уже преднастроены в `servers.json`

Пароли по умолчанию — в `stand/.env.example`. При их смене поправить `stand/links/*.sql`. Секреты в отчёт не включать.

## Сценарий обрыва канала

Центр и объект связаны отдельной сетью `rbd_wan`; клиенты ходят к узлам через собственные сети (`center_net`, `site_net`). Поэтому обрыв `rbd_wan` рвёт межузловой канал, не трогая доступ клиентов:

    ./scripts/demo_disconnect.sh   # обрыв: объект отвязывается от rbd_wan
    # ... регистрируем аномалии на объекте, очередь копится (sync_status = pending)
    ./scripts/demo_reconnect.sh    # возврат канала, репликация догоняет

Замечание для rootless podman: если после `disconnect` порт 5433 перестал отвечать (особенность проброса портов при нескольких сетях), верните сеть (`podman network connect rbd_wan rbd_site`) и как модель отказа центра используйте `podman stop rbd_center`.

## Полный сброс

    cd stand && podman compose down -v
